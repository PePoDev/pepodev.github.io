# Script Optimization Guide

This guide provides best practices for script usage in Astro components.

## Script Directive Best Practices

### When to Use Each Directive

#### 1. **Default `<script>`** - Most Common ✅
```astro
<script>
  // Bundled, optimized, and deduplicated by Vite
  // Use this for most scripts
  const button = document.querySelector('button');
  button?.addEventListener('click', () => {
    console.log('clicked');
  });
</script>
```

**Benefits:**
- Bundled and minified by Vite
- Deduplicated across multiple component instances
- Tree-shaken and optimized
- Supports TypeScript

**Use when:**
- Script can run after page load
- Logic is common across component instances
- You want optimal bundle size

#### 2. **`is:inline`** - Use Sparingly ⚠️
```astro
<script is:inline>
  // Inlined directly in HTML, runs immediately
  // Not bundled or optimized
  localStorage.setItem('theme', 'dark');
</script>
```

**Drawbacks:**
- No bundling or minification
- No TypeScript support
- Duplicated for each component instance
- Can block rendering

**Only use when:**
- Must run before page hydration
- Needs to access `define:vars` data
- Manipulates critical render path
- Prevents flash of unstyled content (FOUC)

#### 3. **`is:raw`** - Rare Use Cases 🔒
```astro
<script is:raw>
  // Not processed at all - passes through as-is
  // Use for third-party scripts that shouldn't be modified
</script>
```

**Use when:**
- Embedding third-party scripts
- Script must not be modified

## Optimization Opportunities

### Example: WelcomeApp Quote Randomization

**Current (is:inline):**
```astro
<script is:inline>
  const quotes = [...];
  const quoteBox = document.getElementById('quote-box');
  // ...
</script>
```

**Optimized (regular script):**
```astro
<script>
  const quotes = [
    "The only way to do great work is to love what you do.",
    // ...
  ];
  
  const quoteBox = document.getElementById('quote-box');
  if (quoteBox) {
    // Logic here
  }
</script>
```

### Example: External Script File

For larger scripts, consider external files:

```astro
<!-- Component -->
<div id="game-container"></div>

<script src="@/scripts/snake-game.ts"></script>
```

```typescript
// src/scripts/snake-game.ts
export function initSnakeGame() {
  const container = document.getElementById('game-container');
  if (!container) return;
  
  // Game logic here
}

// Auto-initialize
initSnakeGame();
```

## Client Directives

For framework components (React, Vue, Svelte), use client directives:

```astro
---
import Counter from './Counter.jsx';
---

<!-- Load immediately -->
<Counter client:load />

<!-- Load when visible -->
<Counter client:visible />

<!-- Load when idle -->
<Counter client:idle />

<!-- Only on client, never on server -->
<Counter client:only="react" />
```

## Performance Tips

1. **Minimize `is:inline`**: Convert to regular scripts where possible
2. **Extract common logic**: Use utility functions in separate files
3. **Defer non-critical**: Use regular scripts for non-critical functionality
4. **Type safety**: Regular scripts support TypeScript
5. **Bundle analysis**: Check bundle size impact with `pnpm build --verbose`

## Migration Checklist

When converting `is:inline` to regular script:

- [ ] Remove `is:inline` attribute
- [ ] Ensure script doesn't use `define:vars` (or find alternative)
- [ ] Add null checks for DOM queries
- [ ] Test that timing still works (DOMContentLoaded if needed)
- [ ] Verify functionality works across page loads
- [ ] Check bundle size impact

## Testing After Migration

```bash
# Build and check bundle size
pnpm build

# Run E2E tests
pnpm test:e2e

# Manual testing
pnpm dev
# Test the specific component functionality
```
